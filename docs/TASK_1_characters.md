# 依頼1：カードゲームを削除し、キャラ10体と図鑑を作り直す

このゲームを「ガチャで集めたマッチ神を、文章から作った能力で戦わせるゲーム」に作り替える。
全体は3つの依頼に分けてあり、これはその1つ目（**キャラと図鑑**）。対戦とクエストは依頼2・3で行う。

| 場所 | 中身 |
|---|---|

## 1. カードゲーム要素をすべて削除する

次をゲームから取り除く。関連する画面・データ・保存項目・文言もすべて消す。

- デッキ編集、カードの能力（キーワード・固有能力・奥義・縁・型・代表個体）
- クエストとカードバトルの画面、バトルの計算（`Battle` クラス）
- アーティファクトと工房
- 守護者システム（スキル・必殺技・ゲージ、`data/guardians.js`）
- ミッション「クエストに1回勝つ」
- 称号のバトル用のオマケ（攻撃+1など。称号そのものは残す）
- `tools/sim.js` のカードバトル部分（個体値と称号の確認は残す）

**残すもの**：ガチャ、図鑑、個体値と称号、保管庫と送り出し、世界ランキング、ログインボーナス、ミッション（上記以外）、探索、設定、画像の登録。

冒険タブは「日課・探索」だけになる。タブの中の「クエスト」「デッキ」の切り替えは消す（クエストは依頼3で作り直す）。

## 2. キャラを入れ替える

- 今のキャラ（座ブラーズと仮キャラ）は**ガチャと図鑑から外す**
- ただし消さずに `archive/` フォルダへ移し、ゲームからは読み込まない（座ブラーズは将来戻す可能性がある）
- 新しいキャラは下の10体。**ガチャはこの10体だけ**から出る
- 保存データのキーを変えて（例：`gachaZukanDemo_v3`）、**これまでの記録はリセット**する（番号が変わるため）

## 4. 文章ファイルの読み込み

文章はすべて用意済み。作る必要はなく、**読み込んで表示する仕組み**だけ作る。

### 図鑑の文章：`stories/chr_001.js` 〜 `chr_010.js`
今の `registerStory` と `loadStory` の仕組みのまま使う。★1には「分類」「種類」「等級」「マッチアビリティ」などの項目が入っているキャラもあるので、今の表示（短い項目は表、長い文章はたためる形）で出す。

### 戦闘能力：`combat/chr_001.js` 〜 `chr_010.js`（新しいフォルダ）

```js
registerCombat('chr_001', {
  type: '重装甲・長期戦特化型',     // 戦闘タイプ
  sections: [
    ['基本戦闘スタイル', `……`],    // [見出し, 文章] を書かれた順に並べてある
  ]
});
```

- `registerCombat` と、図鑑を開いたときに読み込む `loadCombat` を、`registerStory` / `loadStory` と同じ形で作る
- No.002 バースクライは、見出しが「概要：」で始まるまとまり（短い版）が先、そのあとに詳しい版が続く
- 文章中の「攻撃力9」などの古い数字は、作者の元の文章なので**そのまま表示する**（能力値の表示には `characters.js` の値を使う）

## 5. 図鑑のキャラページ

`docs/TASK_zukan_page.md` の形（上に大きな絵、下にタブ）がすでに入っていれば、その「バトル」タブを「**戦闘能力**」タブに置き換える。まだ入っていなければ、ここで一緒に作る。

タブは **基本／物語／戦闘能力／記録** の4つ。

### 上部（絵の下）
- 名前、異名
- **等級のラベル**（下の色）。マッチ守護者は「A級（守護者）」のように両方表示
- 分類・種類

| 等級 | 呼び名 | 色の目安 |
|---|---|---|
| F | 微神級 | 灰色 |
| E | 小神級 | 緑 |
| D | 常神級 | 青 |
| C | 強神級 | 黄 |
| B | 大神級 | オレンジ |
| A | 超神級 | 赤 |
| S | 神話級 | 紫 |
| ORIGIN | 特殊等級 | 青緑 |

### 戦闘能力タブ
- 一番上に**戦闘タイプ**をラベルで表示
- **能力値6つ**を横棒グラフで表示（100を基準の長さにし、100超えははみ出して目立つようにする）
- **覚悟**（低い・ふつう・高い）と**性質タグ**をラベルで表示
- その下に `combat/` の各まとまりを、図鑑の文章と同じ**たためる形**で並べる（最初の1つだけ開いた状態）

### 基本タブ
今の「基本」の内容に加え、マッチアビリティの名前と説明を表示する。

## 6. 完了の条件

1. ゲームのどこにも、カード・デッキ・クエスト・アーティファクト・守護者の画面や文言が残っていない
2. ガチャを引くと、10体だけが出る。図鑑は No.001〜010 の10体
3. 10体すべてで、図鑑の4つのタブが表示され、画像・★1〜★5の文章・戦闘能力の文章が出る
4. `stories/` と `combat/` の文章が、ファイルの内容そのままに表示される（書き換え・省略がない）
5. 等級のラベルと色、能力値の棒グラフ、覚悟、性質タグが正しく出る
6. 保管庫、送り出し、ランキング、ログインボーナス、ミッション、探索がこれまでどおり動く
7. 古い保存データがあっても、エラーにならずに新しい状態から始まる
8. `node --check js/game.js` が通り、`node tools/sim.js stats` で個体値と称号の確認ができる
9. 幅360〜430pxのスマホ縦画面で崩れない

## 7. 変えてほしくないもの

- `stories/` と `combat/` の文章（一字一句）
- 画像ファイル
- 個体値の出にくさ（パワーなどの仕組み）、称号の条件
- ガチャの確率と値段

## 8. 次の依頼との関係

- 依頼2（対戦の仕組み）で、`stats`・`resolve`・`tags`・`grade` と戦闘能力の文章を使って1対1の対戦を作る
- 依頼3（クエスト）で、33ステージを作る
- そのため、上のデータ項目の名前（`stats` `resolve` `tags` `grade`）は変えないこと
