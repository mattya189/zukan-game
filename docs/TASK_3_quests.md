## 2. data/stages.js の中身

| 名前 | 中身 |
|---|---|
| `STAGES` | キャラ別の試練30。`id`（例 `q001_1`）、`boss`（敵のキャラid）、`level`（1〜3）、`name`、`features`、`events`、`enemyState`、`enemyText`、`eventText`、`goal: { text, check(res) }` |
| `FARM_STAGES` | 周回3。`id`、`name`、`difficulty`、`grades`（敵の等級の範囲）、`reward`、`cooldown`（秒）、`features`、`events`、`enemyInd`、`enemyPower`、`goal` |
| `STAGE_POWER` | キャラ別の試練ごとの敵の強さ（`enemyPower` に渡す） |
| `ENEMY_IND` | 段階ごとの敵の個体値 |
| `QUEST_REWARDS` | 段階ごとの報酬 `{ first, repeat, goal }` |
| `STAGE_HINTS` | キャラごとの攻略のヒント |

### 戦わせ方（GameServer に入口を作る）

```js
// キャラ別の試練
const st = STAGES.find(s => s.id === stageId);
const res = runBattle({
  a: { ch: 自分の個体のキャラ, ind: 自分の個体 },
  b: { ch: CHARACTERS の st.boss, ind: ENEMY_IND[st.level] },
  stage: { name: st.name, features: [...st.features], events: st.events, enemyState: st.enemyState, enemyPower: STAGE_POWER[st.id] }
});
const cleared = res.winner === 0;
const goalDone = cleared && st.goal.check(res);

// 周回：敵は st.grades の等級のキャラからランダム、ind は st.enemyInd、enemyPower は st.enemyPower
```

- **`features` は必ずコピーして渡す**（出来事で書き換わるため）
- 抽選・報酬・時間の判定はすべて `GameServer` の中に書く（例：`questBattle(stageId, uid)`、`farmBattle(stageId, uid)`）

## 3. 報酬と進み具合

### キャラ別の試練

| 段階 | 初回クリア | 2回目以降 | 挑戦目標の初達成 |
|---|---|---|---|
| 1 | 300 | 30 | +100 |
| 2 | 800 | 60 | +300 |
| 3 | 2000 ＋「撃破の証」 | 100 | +800 |

- 段階1は最初から挑戦できる。**段階2は段階1をクリア、段階3は段階2をクリア**すると開く
- 挑戦目標のボーナスは、そのステージで**初めて達成したときだけ**
- 段階3の初回クリアで、そのキャラの「**撃破の証**」を記録する（図鑑の「記録」タブに表示）

### 周回

| 難易度 | 1勝の報酬 | クールタイム | 特別な条件 |
|---|---|---|---|
| 初級 はじまりの草原 | 60 | 30秒 | なし |
| 中級 黄昏の闘技場 | 150 | 2分 | 連勝するほど報酬が増える（1連勝ごとに+10%、最大5連勝で1.5倍）。負けると連勝が切れる |
| 上級 神々の遺跡 | 400 | 5分 | 40ラウンド以内に勝つと報酬1.5倍（`goal.check`） |

- 報酬の上限はなし
- クールタイムは**挑戦するたびに（勝っても負けても）**、その難易度だけ始まる。3つは別々に数える
- 残り時間をクエスト画面に表示する

### 保存データ

`questProgress = { cleared: { q001_1: true, ... }, goals: { ... }, proofs: { chr_001: true, ... }, farmReadyAt: { farm_1: 時刻, ... }, arenaStreak: 0 }`
古い保存データには無いので、読み込み時に空の形で補う。

### ミッション
依頼1で消したミッション「クエストに1回勝つ」を**「クエストか周回で1回勝つ」**として戻す。

## 4. 画面

### クエスト一覧（冒険タブの「クエスト」）
- **キャラ別の試練**：10体のカードを図鑑番号順に並べる。カードには絵・名前・等級と、3段階の状態（未解放／挑戦可／クリア／目標達成）を小さな印で表示。撃破の証があれば目立つ印を付ける
- **周回**：3つの難易度を並べ、報酬・クールタイムの残り時間・中級の連勝数を表示

### 挑戦前の画面
`docs/quest-prototype.html` の「ステージ詳細」と同じ内容を出す。
- 舞台の名前と特徴（`STAGE_FEATURES[特徴].text`）
- 敵：キャラの絵・名前・等級・覚悟（周回は「○級からランダム」）
- 敵の状態（`enemyText`）、出来事（`eventText`）、挑戦目標（`goal.text`）、報酬、攻略のヒント（`STAGE_HINTS[boss]`）
- 保管庫から自分の個体を選ぶ一覧（依頼2と同じ部品を使う）
- 「挑戦する」ボタン

### 戦闘画面
依頼2の対戦画面をそのまま使う（1画面、実況のまとめ、結果まで飛ばす、「戦わせる」の挙動）。
結果の欄に次を出す。
- クリア／敗北、勝った側、理由、ラウンド数
- もらった報酬（初回か2回目以降か、目標ボーナス、周回の連勝や1.5倍）
- **挑戦目標の達成・未達成**。結果の欄は濃い背景なので、目標の枠は**白い背景に濃い文字**、「達成！」は緑、「未達成」は赤で、はっきり読めるようにする（試作で白い文字が読めなかったため）
- 「もう一度挑戦」「クエスト一覧へ」のボタン

1. 冒険タブにクエストがあり、キャラ別の試練30と周回3が遊べる

4. 保存データに進み具合が残り、ページを開き直しても続きから遊べる
5. 挑戦前の画面に、特徴・敵の状態・出来事・目標・報酬・ヒントが出る
6. 結果の欄の目標の文字が、明るい表示・暗い表示のどちらでも読める
7. `node tools/stage-sim.js` が動き、段階1〜3の勝率がおおよそ75%・50%・25%になっている
8. `node tools/battle-sim.js` の結果が依頼2と同じ（ラウンド数の中央30〜50、全体の勝率）
9. `node --check` が `js/game.js`・`js/battle.js`・`data/stages.js` で通る
10. 既存の保存データで開いてもエラーが出ない
